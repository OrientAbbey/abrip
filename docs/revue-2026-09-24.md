## Correction appliquée (critique)

### C1 ✅ corrigé — Path traversal sur la route SPA

- **Fichier** : `src/abrip/api/main.py` (route catch-all `/{full_path:path}`)
- **Détail** : la route servait `static_dir / full_path` sans contrôle de
  confinement. Vérifié en conditions réelles : `GET /..%2f..%2fconfigs%2fsettings.yaml`
  renvoyait le contenu du fichier `settings.yaml` (code 200). Un déploiement
  pouvait ainsi exposer `catalog.duckdb`, les YAML de configuration et, sur
  Linux, `/proc/self/environ` (jetons Cloudflare, `ABRIP_API__API_KEY`).
- **Correctif** : le chemin demandé est dorénavant résolu (`Path.resolve()`),
  qui normalise le `..` décodé par Starlette, puis servi **uniquement** s'il
  reste strictement dans `frontend/dist` (`root in candidate.parents`). Tout
  chemin extérieur retombe sur `index.html`.
- **Test de régression** : `tests/test_api.py::TestErreurs` →
  `test_pas_de_lecture_hors_frontend` (ignorée proprement si le frontend n'est
  pas compilé).

## Trouvailles Requises — backend (à traiter)

### R1 — `api_key` n'est jamais appliquée (`src/abrip/api/deps.py:147`)
La fonction `verify_api_key` existe mais **aucune route ni aucun routeur ne
déclare `Depends(verify_api_key)`** (`src/abrip/api/main.py:66-67`). Un
déploiement qui pose `api.api_key` croit être protégé ; chaque endpoint `/api`
reste public. Sécurité silencieuse morte.
Fix : brancher la dépendance sur les routeurs (ou supprimer l'option pour
qu'elle ne trompe pas). Comparaison en temps constant (`hmac.compare_digest`).

### R2 — L'historique des métriques est écrasé chaque jour (`src/abrip/analytics/metrics.py:466-477`)
`_persist` appelle `write_frame(..., replace=True)` qui efface tous les
`*.parquet` du dossier cible. Le `abrip pipeline` quotidien calcule **une seule
journée** : une série `metric_visibility`/`metric_country` de 30 jours s'effondre
à un point à chaque exécution. Les événements/incidents persévèrent par
identifiant déterministe, pas les métriques.
Fix : partitionner l'écriture par `window_start` (fusion dans la partition
existante, comme la curation RIS Live) ou fusionner les fenêtres superposées.

### R3 — La curation RIB accumule tout en mémoire (`src/abrip/etl/curate.py:136-183`)
`rows: list[dict] = []` bufferise **l'intégralité** d'un snapshot
(day, collector) avant matérialisation. Un vrai snapshot RouteViews/RIS fait
10⁷–10⁸ lignes `(peer, prefix)`. Contredit le contrat mémoire bornée documenté
(8 Go cible, pic < 1,5 Go) pourtant tenu par `curate_day` (qui stream via
`ParquetBatchWriter`).
Fix : envoyer la sortie du parseur dans un `ParquetBatchWriter` (schéma
`RIB_SNAPSHOT_SCHEMA`, `batch_rows`) et prendre le timestamp du premier
enregistrement.

### R4 — Le parseur PCH charge tout le dump en mémoire (`src/abrip/etl/pch_parser.py:137`)
`lines = handle.readlines()` matérialise le fichier texte complet (des millions
de lignes possible) avant le moindre parsing.
Fix : itérer `handle` ligne par ligne ; les ~20 premières lignes suffisent pour
la détection d'en-tête (`itertools.islice`), puis streamer le reste.

### R5 — Le broker BGPKIT ne lit que la première page (`src/abrip/ingestion/broker.py:70-97`)
`page_size: 1000` et pas de suivi de pagination. À 15 min par fichier
(≈96/jour/collecteur), toute plage > ~10 jours dépasse 1000 résultats et les
fichiers restants sont **silencieusement omis** de l'ingestion — un trou complet
dans la donnée curée que rien ne signale.
Fix : boucler sur la pagination (offset/curseur) ou au minimum journaliser un
avertissement de troncature. Garder le repli sur les URLs d'archive.

### R6 — `/api/asns?country=X` → 500 si `ref_asn` absent (`src/abrip/api/routers/explore.py:30-39`)
Le filtre `country` ajoute `r.country_iso2 = ?` sans vérifier que `ref` existe ;
l'alias `r` n'est jamais joint → erreur DuckDB → handler générique → 500. Le
filtre `african_only` est, lui, correctement conditionné par `if ref` (ligne 33).
Fix : conditionner `country` sur la présence de `ref` (ou `data.require("ref_asn")`
pour un 503 porteur de la commande correctrice).

### R7 — Écritures DuckDB concurrentes → verrous (`src/abrip/ingestion/downloader.py:80-97`)
Chaque worker du pool ouvre sa propre connexion DuckDB et écrit dans
`ingestion_log` ; DuckDB est mono-écrivain, les transactions chevauchées
échouent sporadiquement (`could not set lock`). Conséquence sournoise : le
fichier télécharge mais sa trace journal manque → re-téléchargement la nuit
suivante.
Fix : sérialiser l'accès au catalogue derrière un `threading.Lock` (lectures
bon marché, écritures courtes).

### R8 — Validation RPKI en boucle Python ligne à ligne (`src/abrip/analytics/metrics.py:383-390`)
`rw` parser, `announced` peut compter des centaines de milliers de couples
(prefixe, origine). `validator.validate` est appelé par ligne, chacun refaisant
les recherches supernet O(prefixlen+1). `RpkiValidator.validate_frame`
(écrit pour cela) n'est pas utilisé.
Fix : passer `announced` à `validate_frame` puis agréger par pays.

### R9 — La curation RIS Live relit/réécrit toute la journée (`src/abrip/etl/curate.py:186-235`)
Chaque fenêtre de 5 min charge la partition du jour en mémoire, déduplique et
réécrit. Sur une journée de fenêtres continues : O(n²) et mémoire O(n) à chaque
fenêtre. Le flux continu `detect watch` est concerné.
Fix : persister chaque fenêtre comme un « part » séparé et laisser
`read_partitions` dédupliquer, ou fusionner dans un staging par jour à la fermeture.

## Trouvailles Requises — frontend & tests (à traiter)

### FR1 — Dates UTC décalées hors UTC (`frontend/src/lib/format.ts:26-27`)
Les datetimes backend sont naïves (pas de fuseau) et sérialisées sans offset.
`new Date(value)` parse la chaîne en **heure locale** puis formate en UTC, tout
en affichant « UTC » — chaque horodatage est décalé du décalage du navigateur.
Même chemin naïf dans `TimeChart.tsx` (ticks) et `EventDetail.tsx`.
Fix : parser en UTC (`value.endsWith("Z") ? value : value + "Z"`) ou faire
émettre des datetimes horodatées par l'API (`.replace(tzinfo=UTC)`).

### FR2 — Pagination des ASN cassée (`frontend/src/pages/AsnList.tsx:30`)
`update()` exécute **inconditionnellement** `next.delete("offset")` : l'offset
que les boutons Précédent/Suivant viennent de poser est effacé avant `setParams`
→ l'URL ne porte jamais `offset`, chaque page affiche les items 1–25.
`Prefixes.tsx:26` fait le bonne chose (`if (key !== "offset") …`).
Fix : recopier la garde de `Prefixes.tsx`.

### FR3 — Le test de rappel ne vérifie pas le détecteur attendu (`tests/test_detection.py:84-94`)
`verify()` compte une anomalie plantée comme trouvée sur la seule égalité
`(prefixe, date)` ; `expected_detector_fired` est calculé dans chaque entrée
(`src/abrip/demo/bootstrap.py:92-104`) mais **jamais asserté** par le test — qui
ne vérifie que `recall == 1.0`. Un détecteur qui se tait passe encore si un
autre se déclenche sur le même préfixe ce jour-là.
Fix : asserter `all(m["expected_detector_fired"] for m in report["matched"])`.

### FR4 — `test_prefixes_routables` est tautologique (`tests/test_normalize.py:89-93`)
Il n'asserte que `isinstance(is_bogon_prefix(p), bool)` — vrai pour n'importe
quel renvoi de booléen. Le commentaire concède que `2001:db8::/32` est un bogon
documenté, pourtant ce cas est dans la liste « routable », et l'assertion
passerait si la fonction renvoyait `True` pour tout IPv6.
Fix : asserter les classements réels (`is False` pour `197.155.64.0/22`,
`is True` pour `2001:db8::/32`).

### FR5 — La confirmation RIPE Atlas ignore la fenêtre (`src/abrip/enrichment/dataplane.py:290`)
`confirm_event` honore `first_seen`/`last_seen` pour IODA et Radar mais appelle
`atlas.connectivity_ratio(country=…)` **sans bornes de temps** : la corroboration
reflète l'état des sondes au moment de l'enrichissement, pas pendant l'événement.
Les tests `httpx.MockTransport` ne peuvent pas attraper ça (le mock ignore le
temps).
Fix : borner l'appel Atlas à la fenêtre (endpoint historique) ou ré-étiqueter la
preuve « état actuel des sondes ».

### FR6 — Les tests de non-régression sautent sur checkout frais (`tests/test_api.py:23-32`, `tests/test_detection.py:73-79`)
`requires_data`/`requires_pipeline` skippent quand `data/` est absent : un CI
propre n'exerce **jamais** le rappel de détection ni les requêtes API, et un jeu
commité les fait passer pour toujours sans toucher aux nouvelles données.
Fix : construire le jeu de démo en session sous `tmp_path` (motif déjà présent
dans `test_ris_live_curation.py`) ou faire tourner `abrip demo bootstrap` dans
le CI et échouer bruyamment si l'étape manque.
